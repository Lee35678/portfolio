  • 교육장 기기에서만 되던 가입·수료증 재발급을 위해 같은 회원 DB를 쓰는 회사 웹사이트를 제안·구현했습니다.

  • 측정 도구를 만들면 정답을 아는 짧은 입력으로 도구부터 검증합니다.
  • 임계값 조정용 촬영과 평가용 촬영을 처음부터 나눠 모읍니다.
  • "반영됐다"고 보고하기 전에 서비스 재시작과 실제 응답 값을 확인합니다.
  • 평가 계획에 시스템을 모르는 외부인 촬영을 넣습니다.

협업 방식

계약을 먼저 정하고 나눠서 개발

팀 저장소를 처음 만들 때 서비스 4개의 뼈대와 서비스 사이에 주고받을 데이터 형식(JSON 스키마 4종)부터 정했습니다. 덕분에 4명이 각자 다른 서비스를 동시에 만들 수 있었습니다.

서비스별 브랜치와 통합 브랜치

vision·web·actuation·picar·data를 각자 기능 브랜치에서 만들고 dev 브랜치에 모았습니다. 4개 서비스의 1차 통합 병합을 맡았습니다.

테스트로 작업을 넘겨받기

팀원이 응답 판정 기준표와 인수 테스트 22개를 먼저 쓰고, 그 테스트를 통과하는 코드를 구현했습니다. 목표일보다 이틀 빠르게 병합됐습니다.

실험은 운영 코드와 분리

딥러닝 비교 연구는 별도 브랜치에서 진행하고 dev에 병합하지 않았습니다. 결론만 문서로 옮겨 운영 코드에 섞이지 않게 했습니다.

결정은 근거와 함께 기록

회의 자료마다 선택지·근거 수치·권고를 붙였고, 안건별 결정권자를 정해 결정을 기록했습니다. 화면 디자인을 바꿀 때도 화면 흐름과 기능 계약은 그대로 두어 팀원이 만든 테스트가 계속 통과하게 했습니다.
