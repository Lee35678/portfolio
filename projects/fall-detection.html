카메라 낙상 감지

졸업 작품(독거노인 관리 시스템)의 낙상 감지를 맡아, 규칙 기반 판정에서 학습 모델 후보까지 세 가지 방식으로 만들어 봤습니다.

GitHub · 학습 모델 후보 GitHub · MoveNet 판정 GitHub · 배경 차분 규칙
TEAM4인 팀 졸업 작품
MY ROLE낙상 감지 방식 3가지 구현

규칙 2가지, 학습 모델 후보 1가지, 휴대폰 알림

DATAUBFC Fall Detection Dataset

학습 모델 후보에 사용

졸업 작품의 최종 낙상 모델은 픽셀 특징 대신 MediaPipe Pose 관절 좌표를 입력으로 쓰는 Bi-LSTM과 URFD 데이터셋으로 정해졌습니다(졸업논문 4장).

세 가지 방식

방식어떻게 판단하나한계 · 다음 방식으로 넘어간 이유
① 배경 차분 규칙
2025.03움직이는 영역의 경계 상자 높이/너비 비율이 0.5 미만으로 2초 이상 지속되면 낙상사람이 아닌 움직임에도 반응하고, 몸의 자세를 직접 보지 못합니다.
② MoveNet 관절 규칙
2025.05 – 06코의 낙폭과 몸통 각도 변화로 의심한 뒤, 4프레임 안에 몸이 수평이고 코가 엉덩이보다 아래이면 확정. 확정되면 FCM으로 휴대폰에 알림임계값을 사람이 정하는 규칙이라, 넘어지는 모양이 다양하면 대응하기 어렵습니다.
③ 학습 모델 후보
2025.06MobileNetV2로 프레임 특징을 뽑고, 32프레임 흐름을 LSTM으로 분류무작위 분할 검증만 했고, 픽셀 특징이라 조명·배경 영향을 받습니다. 최종 모델은 관절 좌표 입력으로 바뀌었습니다.

학습 모델 후보의 구조

학습프레임 32×224×224×3→MobileNetV2 (ImageNet, 고정)→특징 32×1280→LSTM(128) → Dropout 0.3 → Dense(sigmoid)
실시간웹캠 프레임→224×224 · 0~1 정규화→MobileNetV2→최근 32프레임 유지→확률 > 0.5 → FALL DETECTED

돌아보기

  • 클립 단위 무작위 분할이라 같은 장소·같은 인물의 클립이 학습과 검증에 함께 들어갈 수 있습니다. 99.42%는 처음 보는 환경에서의 성능이 아닙니다.
  • 모델 파일을 못 읽으면 학습되지 않은 더미 모델로 조용히 실행되는 경로가 있었습니다. 결과가 틀려도 알아차리기 어렵습니다.
  • 영상을 프레임 묶음으로 바꾸는 스크립트가 저장소에 없어, 같은 결과를 다시 만들기 어렵습니다.
