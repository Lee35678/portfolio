1차 2025.03 · 개선판 2025.05 – 06

MY CONTRIBUTION
  • 하이브리드 호출어 인식: 오프라인 키워드 감지 + STT 문구 가중치
  • 음성 인식(Google Cloud STT)과 명령 처리
  • 웹 검색 결과를 근거로 답하는 RAG 말벗 기능(Gemini)
  • 음성 출력과 단계별 대체 경로(VAD·TTS·클라우드 인증)
  • MoveNet 관절 좌표 기반 2단계 낙상 판정
  • Firebase Cloud Messaging 토픽 푸시, 안드로이드 수신 예시

팀 시스템의 다른 구성 요소 · 라즈베리파이 4B 중심 구성, 아두이노와 SG90 서보모터로 움직이는 팬·틸트 카메라, C# WinForms 관리자 프로그램(실시간 영상·카메라 제어·응급 알림), 소리 크기 기반 응급 감지, URFD 데이터셋 Bi-LSTM 낙상 모델

왜 만들었나

2025년 3월 기준 65세 이상 인구가 전체의 20.4%이고, 고령자 1인 가구는 전체 가구의 8.9%입니다(2022년). 복지 지원은 지역 역량에 따라 차이가 커서 사각지대가 생깁니다. 그래서 넘어지는 순간을 보호자·기관에 바로 알리고, 외로움을 덜어 줄 말벗을 함께 제공하는 시스템을 목표로 했습니다.

통계 출처 · 졸업논문 서론(국가데이터청 장래가구추계 2022–2052 인용)

음성 비서 파이프라인

입력마이크 16kHz 모노→음성 구간 감지 (webrtcvad, 없으면 음량 기준)
호출오프라인 키워드 감지 "shee-bee-ya"+STT 문구 가중치 boost 20→효과음 후 명령 대기
처리Google Cloud STT→시간·종료는 기기에서 처리/그 밖의 질문은 웹 검색 5건 + Gemini 종합
출력Google Cloud TTS→실패하면 gTTS→스피커

설계 판단

선택이유대안
하이브리드 호출어

노인 사용자는 발음이 분명하지 않을 수 있습니다. 오프라인 키워드 감지로 네트워크 지연 없이 바로 녹음을 시작하고, STT에는 "실비야·실비아·실비·비아" 같은 비슷한 발음 목록에 가중치 20을 줘서 부정확하게 불러도 알아듣게 했습니다.

정확한 발음 하나만 인식
검색 결합 답변(RAG)

언어 모델만으로는 날씨 같은 최신 정보에 약합니다. 질문으로 웹을 검색해 상위 5개 결과를 근거로 답하게 하고, 링크나 기호 없이 말로 설명하듯 답하도록 프롬프트를 정했습니다(temperature 0.3).

Gemini 단독 답변
단계별 대체 경로

혼자 사는 사람이 의지하는 기기라 멈추면 안 됩니다. 음성 구간 감지 모듈이 없으면 음량 기준으로, 클라우드 음성 합성이 실패하면 gTTS로 넘어가고, 클라우드 인증이 없어도 프로그램이 죽지 않고 실행되게 했습니다.

한 경로만 사용

웹캠 낙상 감지와 알림 · 1차 버전에서 개선판으로

낙상웹캠→MoveNet Lightning 192×192→1단계 의심→2단계 확인→FCM fallAlerts 토픽→안드로이드 앱
항목1차 · 2025.03개선판 · 2025.05 – 06
낙상 판단배경 차분으로 움직이는 영역을 찾고, 경계 상자의 높이/너비 비율이 0.5 미만으로 2초 이상 지속되면 낙상관절 좌표로 코의 낙폭과 몸통 각도 변화를 보고 의심한 뒤, 4프레임 안에 몸이 수평이고 코가 엉덩이보다 아래이면 확정
알림화면 표시와 로그 파일FCM 토픽 푸시로 휴대폰 알림, 5초 안의 중복 알림은 보내지 않음
음성 인식SpeechRecognition의 웹 음성 인식, 호출어 "재용아"Google Cloud STT와 하이브리드 호출어 "실비야"
답변알람·날씨는 규칙 처리, 나머지는 Gemini 단독 답변웹 검색 결과를 근거로 한 RAG 답변
실행 구조음성 비서와 낙상 감지를 각각 따로 실행한 런처에서 동시 실행(음성은 백그라운드 스레드)

배경 차분은 사람이 아닌 움직임에도 반응하고, 한 번 크게 움직인 것만으로는 넘어졌다고 보기 어렵습니다. 그래서 의심과 확인을 나눠 한 순간의 움직임만으로 알리지 않게 했습니다.
